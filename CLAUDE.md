## Что здесь

**CosmosCalendar** — зонтичный репозиторий «Космос календаря». Код живёт в двух
сабмодулях, у каждого свой репозиторий, своя история и своя документация:

| Папка | Репозиторий | Что это |
|---|---|---|
| `Calendar/` | [SayxZero/Calendar](https://github.com/SayxZero/Calendar) | планер: Qt 6 / C++17, Windows, Linux, Android |
| `CalendarServer/` | [SayxZero/CalendarServer](https://github.com/SayxZero/CalendarServer) | сервер синхронизации: Qt 6 Core, Network, Sql; Windows и Linux |

Здесь лежит только то, что касается обоих сразу:

- [DESDOC.md](DESDOC.md) — как планер и сервер работают вместе: состав системы,
  протокол, где какие данные, развёртывание и совместимость версий;
- [ISSUES.md](ISSUES.md) — грабли, на которые уже наступали (подгружается ниже);
- [PACKAGING.md](PACKAGING.md) — план установочных пакетов, на будущее;
- [README.md](README.md) — что это и как получить всё одной командой.

Работа над кодом идёт в сабмодулях. У каждого свои `CLAUDE.md` (у планера —
подробный, с архитектурой и соглашениями), `README.md` и `DesDoc.md`.
**Разделение документов:** DesDoc планера не описывает внутреннее устройство
сервера, DesDoc сервера — устройство планера; то, как они говорят друг с
другом, может быть в обоих, а целиком описано в `DESDOC.md` здесь. Так же с
README: о самом проекте подробно, о соседнем — минимум и ссылка.

## Репозитории и коммиты

- **Коммитить и пушить — только когда об этом попросили.**
- **Сначала сабмодуль, потом зонтик.** Коммит и push делаются в сабмодуле, и
  только потом здесь коммитится его новый указатель (`git add Calendar`).
  Указатель на коммит, которого нет на GitHub, ломает
  `git clone --recursive` и `git submodule update` всем остальным.
- **Ветка у всех трёх — `master`**, в `.gitmodules` она прописана, так что
  `git submodule update --remote` берёт именно её.
- **Свежая копия** — `git clone --recursive https://github.com/SayxZero/CosmosCalendar.git`;
  в уже склонированной без сабмодулей — `git submodule update --init`.
- **После `git submodule update` сабмодуль стоит на оторванной голове.** Перед
  правками в нём — `git switch master`, иначе коммит повиснет вне ветки.
- Каталоги `.git` сабмодулей лежат в `.git/modules/` зонтичного репозитория, а
  `Calendar/.git` — файл со ссылкой туда. git внутри `Calendar/` и
  `CalendarServer/` работает как в обычном репозитории.
- `.gitignore` у каждого репозитория свой: здесь — только служебные папки
  инструментов в корне (`.claude/`, `.vs/`), у сабмодулей — их сборка, данные и
  настройки IDE.

## Правила проверок

- **На телефоне настоящий планер пользователя.** Проверки идут только в
  песочнице: `--data-dir /sdcard/Android/data/org.calendarplanner.app/files/testdb --demo`;
  после проверки песочница удаляется, а планер запускается обычным образом
  (он сам вернёт свой снимок виджетов и план будильников). Подробности — в
  `Calendar/CLAUDE.md` и ниже, «Локальное окружение».
- **Виджеты на рабочем столе телефона — пользователя.** Не добавлять и не менять.
- **Сервер на этом ПК обычно запущен** — это боевой экземпляр с аккаунтами, его
  не останавливают. Для проверок поднимается второй, со своим портом и папкой
  данных (`run-server.bat -p 8766 -d <папка>`).
- **Задача в планере заканчивается релизными сборками**: `release/CalendarPlanner.exe`
  и подписанный APK собраны, тесты прошли (`Calendar/CLAUDE.md`, «Релизные
  сборки»). У сервера — его 22 теста.

## Локальное окружение

Рабочая копия — `D:\Prog\Calendar` (папка зовётся по-старому, репозиторий в ней —
CosmosCalendar). История прежнего общего репозитория, где планер и сервер
жили вместе, сохранена бандлом `D:\Prog\Calendar-old-repo-2026-10-25.bundle`
(`git clone <бандл> <папка>` разворачивает её целиком).

Пути на этой машине (в других местах будут свои):

| | |
|---|---|
| Qt | `D:\Qt\6.5.3` — киты `mingw_64`, `msvc2019_64`, `android_*`, `wasm_*` |
| Компилятор | `D:\Qt\Tools\mingw1120_64\bin` |
| CMake, Ninja | `D:\Qt\Tools\CMake_64\bin`, `D:\Qt\Tools\Ninja` |
| Android SDK | `D:\Android\SDK` (NDK `25.1.8937393`, platform `android-33`) |
| JDK | `C:\Program Files\Java\jdk-17` — Gradle из Qt 6.5 не работает с JDK 21+ |

Данные приложения: `%APPDATA%\CalendarPlanner\CalendarPlanner\` (`planner.db`,
`settings.ini`).

**Сервер на этом ПК.** `D:\Prog\Calendar\CalendarServer\build\CalendarServer.exe`,
порт 8765, адрес в домашней сети `192.168.0.146` (Ethernet). Телефон видит его
по Wi-Fi напрямую, брандмауэр пропускает. Если связи нет — `adb reverse tcp:8765
tcp:8765` и адрес `127.0.0.1:8765` на телефоне.

**Тестовый телефон.** Подключён по USB (`adb devices`), Android 13. Экран
блокировки без пароля: если аппарат спит, `adb shell input keyevent
KEYCODE_WAKEUP` и свайп вверх (`input swipe 360 1300 360 400`) открывают рабочий
стол, дальше приложением можно управлять через `adb shell input tap`. Разрешения
спрашивать не у кого — просить владельца разблокировать не нужно.

Снимок экрана телефона — `adb exec-out screencap -p > файл.png`, и **только
через `cmd`**: PowerShell пропускает вывод через кодировку и дописывает BOM,
после чего PNG не открывается. Окно настольной сборки снимается из PowerShell
через `System.Drawing` (`CopyFromScreen` по прямоугольнику из `GetWindowRect`),
а нажать в нём можно `SetCursorPos` + `mouse_event`: так проверяется то, что
видно только глазами, — рамки, цвета, выравнивание. На **заблокированной**
сессии Windows этого нет: `CopyFromScreen` отвечает «The handle is invalid», и
проверять остаётся на телефоне — `adb` работает и при погашенном экране.

На телефоне лежит **настоящий планер пользователя**. Проверки не должны менять
его данные: файл для импорта готовьте отдельный, со своим `X-WR-CALNAME` (он
создаст новый календарь, который потом удаляется вместе с записями), файлы из
`/sdcard/Download` за собой убирайте. Файл с именем существующего календаря
вольёт записи в него — разобрать их обратно будет нечем. `adb push` в Git Bash
требует `MSYS_NO_PATHCONV=1`, иначе путь `/sdcard/...` превращается в
`C:/Program Files/Git/sdcard/...`, а залитый файл до системного выбора не
доберётся, пока его не проиндексирует media store:
`adb shell content call --uri content://media/external/file --method scan_file
--arg /sdcard/Download/<файл>`.

Синхронизацию на телефоне проверяйте **тестовым аккаунтом** на сервере с
отдельной папкой данных: на вопрос «Скопировать события и задачи этого
устройства в аккаунт?» отвечайте «Не копировать», а после проверки выходите из
аккаунта — его копия на устройстве удалится, локальный планер останется
нетронутым. `adb shell input text` не печатает кириллицу: названия тестовых
записей — латиницей. Проверочный будильник («Настройки → Будильник → Проверить
будильник») звучит по-настоящему — через канал будильника, даже без звука
звонка.
